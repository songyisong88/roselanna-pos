# ROSELANNA — เดโมระบบจองคิว / POS / แดชบอร์ด (ข้อมูลตัวอย่าง) · ช่วงที่ 2

ROSELANNA — Thai Massage & Wellness. **ข้อมูลทั้งหมดเป็นข้อมูลตัวอย่าง** ไม่มีการเชื่อม LINE จริง ไม่มีการชำระเงินจริง

## เว็บ 2 ฝั่ง แยกกันเด็ดขาด

| เว็บ | ที่อยู่ | ใช้ทำอะไร |
|---|---|---|
| **เว็บลูกค้า** | `/customer/` | จองคิวแบบหน้าจอ LINE, ดูราคา/โปรโมชั่น, คะแนนสะสม — ไม่มีเมนูหรือลิงก์ของพนักงาน |

## สองโหมดการทำงาน

1. **โหมดเซิร์ฟเวอร์กลาง (ช่วงที่ 2)** — เว็บทั้งสองคุยกับ API (Node.js + SQLite) ข้อมูลอยู่ที่เซิร์ฟเวอร์ ลูกค้าจองจากอุปกรณ์หนึ่ง
   แล้วคิวปรากฏบน POS/แดชบอร์ดของอีกอุปกรณ์ (หน้าเว็บ poll ทุก 3–4 วินาที) กันจองซ้ำห้อง/หมอนวดที่เซิร์ฟเวอร์ และบังคับสิทธิ์ที่เซิร์ฟเวอร์
2. **โหมด localStorage (ช่วงที่ 1)** — ไม่ตั้ง `serverUrl` = ใช้ข้อมูลในเบราว์เซอร์ (GitHub Pages ใช้โหมดนี้) เว็บลูกค้ากับเว็บหลังร้านใช้ localStorage ร่วมกัน
   *เมื่อเปิดในเบราว์เซอร์เดียวกัน* จึงเห็นคิวข้ามแท็บได้ แต่ **สิทธิ์ในโหมดนี้เป็นแค่การซ่อนปุ่มใน UI ไม่ใช่ความปลอดภัยจริง**

เลือกโหมดจาก `js/config.js` (`window.RL_CONFIG = { serverUrl: null }`) เซิร์ฟเวอร์จะแทนไฟล์นี้ให้เองเมื่อเสิร์ฟหน้าเว็บ
(ทดสอบกับเซิร์ฟเวอร์บนเครื่องตัวเองได้ด้วย `?server=http://127.0.0.1:3000` ต่อท้าย URL — รับเฉพาะ localhost)

## รันบนเครื่องตัวเอง

ต้องมี Node.js 20 ขึ้นไป

```bash
cd server
npm install
npm start            # เปิด http://127.0.0.1:3000   (เว็บลูกค้า /customer/ · เว็บหลังร้าน /shop/)
npm start -- --reset # ล้างฐานข้อมูลเดโมแล้วเริ่มใหม่
npm test             # ทดสอบ API อัตโนมัติ (node:test)
```

ตัวแปรสภาพแวดล้อม: `PORT` (3000) · `HOST` (127.0.0.1) · `ROSELANNA_DB` (ไฟล์ SQLite, ค่าเริ่มต้น `server/data/`) ·
`ROSELANNA_CORS` (โดเมนที่อนุญาต) · `ROSELANNA_DEMO_LOGIN=0` (ปิดการเข้าสู่ระบบเดโม) · `ROSELANNA_QUIET=1`

หมายเหตุ: ใช้ `better-sqlite3@11` เพราะเวอร์ชัน 12 ยังไม่มีไฟล์สำเร็จรูปสำหรับเครื่องที่ไม่มีคอมไพเลอร์ (ไฟล์ฐานข้อมูล `*.sqlite` ถูก `.gitignore` ไว้ ไม่ขึ้น GitHub)

### เซิร์ฟเวอร์ทำอะไรบ้าง
- ตาราง: branches, rooms, services, therapists, customers (คะแนน/ระดับ), bookings, sales (ค่าคอม), users, sessions, audit_log, notifications
- กันจองซ้ำ 3 ชั้น: ตรวจใน transaction + trigger ในฐานข้อมูล (ห้อง/หมอนวด) + ทดสอบยิงพร้อมกัน — บริการ 90 นาทีกินเวลา 1.5 ชม.
- ชำระเงิน: คะแนน = ยอดสุทธิ ÷ 10 (ปัดลง) · ค่าคอมหมอนวด 30% · สมาชิกลด 10% / VIP (≥ 2,000 คะแนน) ลด 15%
- แดชบอร์ดรวมต่อสาขา แยกตามสิทธิ์: เจ้าของเห็นทุกสาขา · ผู้จัดการเห็นเฉพาะสาขาตัวเอง · หมอนวดเห็นเฉพาะคิวตัวเอง · แคชเชียร์ไม่มีแดชบอร์ด (ตัวเลขใช้สูตรเดียวกับหน้าเว็บ `js/dashboard-calc.js`)
- เข้าสู่ระบบเดโมแบบ token (เก็บเฉพาะแฮช อายุ 12 ชม.) · ทุกครั้งที่ถูกปฏิเสธสิทธิ์จะบันทึกใน audit_log
- `notifier` (ช่อง `customer_oa`, `staff_oa`) **แค่จดลงตารางและ log** ไม่ส่งอะไรออกไป — ดู [docs/LINE-INTEGRATION.md](docs/LINE-INTEGRATION.md)

## ทดสอบ

```bash
cd server && npm test                    # ทดสอบ API: จองซ้ำถูกปฏิเสธ, สิทธิ์, คะแนน/ค่าคอม, ยอดแดชบอร์ดตรงกับยอดขาย
node tests/e2e-stage2.js server          # Playwright: เปิดเซิร์ฟเวอร์ชั่วคราว ใช้ 2 เบราว์เซอร์คนละ context (ลูกค้าจอง → โผล่ใน POS/แดชบอร์ด)
node tests/e2e-stage2.js local [URL]     # Playwright โหมด localStorage (ค่าเริ่มต้นเสิร์ฟด้วย python http.server; ใส่ URL GitHub Pages ได้)
```
ภาพหน้าจอจากการทดสอบอยู่ที่ `shots/stage2/` (ต้องมี Playwright และ Google Chrome)

## ตัวเลือกโฮสต์เซิร์ฟเวอร์กลางจริง (เป็นแค่ตัวเลือก — ยังไม่ได้สมัครหรือติดตั้งที่ไหน)

ราคาตรวจจากหน้าราคาทางการเมื่อ 26 ต.ค. 2569 เป็นดอลลาร์สหรัฐต่อเดือน ยังไม่รวมภาษี และอาจเปลี่ยนได้ (1 ดอลลาร์ ≈ 33–36 บาท โดยประมาณ)
เซิร์ฟเวอร์นี้ใช้ไฟล์ SQLite จึง **ต้องมีดิสก์ถาวร** (ไม่งั้นข้อมูลหายเมื่อรีสตาร์ต)

| ตัวเลือก | ราคาโดยประมาณ | ต้องสมัครอะไร | ข้อสังเกต |
|---|---|---|---|
| **Render** (render.com) | แผนจ่ายเงินเริ่ม **$7/เดือน** (0.5 CPU, 512 MB) + ดิสก์ถาวร **$0.25/GB/เดือน** (≈ $7.25 ถ้าดิสก์ 1 GB) | บัญชี Render + บัตร | แผนฟรี (512 MB) **ใช้กับ SQLite ไม่ได้**: ไม่มีดิสก์ถาวร ไฟล์หายทุกครั้งที่รีสตาร์ต และหลับเมื่อไม่มีคนใช้ 15 นาที (ตื่นช้า ~1 นาที) |
| **Fly.io** (fly.io) | เครื่องเล็กสุด shared-cpu-1x 256 MB **$2.19/เดือน** (แนะนำ 512 MB = $3.69) + volume **$0.15/GB/เดือน** + ข้อมูลออก $0.04/GB (เอเชีย) | บัญชี Fly + บัตร | ไม่มีแผนฟรีสำหรับบัญชีใหม่ (ทดลองใช้ได้ 2 ชม. หรือ 7 วัน) ราคาต่ำที่สุดในกลุ่มจ่ายเงิน ต้องใช้ command line ในการติดตั้ง |
| **Railway** (railway.com) | **$5/เดือน** (รวมเครดิตใช้งาน $5) + ส่วนที่เกิน; volume ≈ $0.15/GB/เดือน | บัญชี Railway (เชื่อม GitHub) + บัตร | ทดลองฟรี $5 ครั้งเดียว 30 วัน; แผนฟรีหลังจากนั้นเครดิต $1/เดือน (ไม่พอสำหรับร้านจริง) ตั้งค่าง่ายสุดสำหรับมือใหม่ |
| **Oracle Cloud Always Free** | **$0** (แต่ต้องใส่บัตรยืนยันตัวตน) | บัญชี Oracle Cloud | ฟรีถาวร: VM แบบ ARM 2 CPU / 12 GB (ลดจาก 4 CPU / 24 GB เมื่อ 15 มิ.ย. 2569) หรือ AMD micro 1 GB ×2 แต่ต้องดูแลเซิร์ฟเวอร์เอง (ติดตั้ง Node, HTTPS, สำรองข้อมูล) และบางครั้งสร้างไม่ได้เพราะเครื่องเต็ม — เหมาะกับคนที่มีช่างเทคนิค |

ค่าใช้จ่ายอื่นที่อาจมี: โดเมนของร้าน (ราคาต่อปีขึ้นกับผู้ขาย ยังไม่ได้ตรวจ) · ค่าข้อความ LINE ตามแพ็กเกจ OA (ดู [docs/LINE-INTEGRATION.md](docs/LINE-INTEGRATION.md): ฟรี 300 ข้อความ/เดือน, เบสิก ฿1,280 + VAT)

**คำแนะนำ:** ถ้าไม่มีช่างเทคนิคประจำ ให้เริ่มที่ Railway หรือ Render (ประมาณ ฿250/เดือน) ส่วน Fly.io ถูกกว่าแต่ตั้งค่ายากกว่า — ก่อนใช้จริงต้องเพิ่มรหัสผ่านพนักงานจริงและปิด demo login

## ข้อจำกัดที่รู้อยู่ (เดโม)
- การเข้าสู่ระบบพนักงานเป็นแบบเดโม ไม่มีรหัสผ่าน (ของจริงต้องมี) · ลูกค้าเดโมคือ "c-demo" แทนการล็อกอิน LINE
- คิวของ "พรุ่งนี้" กดเริ่มบริการและชำระได้ (ของจริงควรล็อกไว้ให้ทำได้เฉพาะวันนั้น)
- แผง "วัตถุดิบใกล้หมด" และจำนวน "ลูกค้าที่ยังไม่กลับมา" เป็นตัวเลขตัวอย่างคงที่
- เซิร์ฟเวอร์ใช้เวลากรุงเทพ (UTC+7) · โหมด localStorage ไม่มีการบังคับสิทธิ์จริง
- LINE ยังไม่ได้เชื่อมจริง (ไม่มี token/webhook) — ข้อความถูกจดลงตาราง `notifications` เท่านั้น
